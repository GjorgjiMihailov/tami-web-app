# Стоков извештај — PDF извоз со набавна и продажна вредност (сп#7)

Датум: 2026-07-31
Статус: одобрено од корисник, чека финален преглед на овој документ

## Контекст

Ова е сп#7 (последен) од серијата корекции по живо тестирање. Сп#6 (Артикли)
додаде поле `selling_price` (продажна цена, без ДДВ) на `Item`. Досега извештајот
„Залиха" (`StockOnHandReport` / `StockLevelQuery::stockOnHand()` /
`stockOnHandTotals()`) прикажува само набавна вредност (количина × просечна
набавна цена). Овој сп#7 додава продажна вредност веднаш до неа, на екран и во
нов PDF извоз.

Извештајот „Вреднување на залихи" (`StockValuationReport`, групирано резиме по
магацин/категорија/вкупно) **не** е во опфатот на овој сп#7 — останува
непроменет.

Вкупна вредност на цел магацин (сумирано преку сите артикли, различно од
постоечкото „вкупно по артикл преку сите магацини") е забележана од корисникот
како идна желба, но е надвор од опфатот сега.

## 1. Пресметки (`StockLevelQuery`)

И `stockOnHand()` и `stockOnHandTotals()` (во `app/Services/Inventory/StockLevelQuery.php`)
join-ираат `items.selling_price` и додаваат по едно ново пресметано поле:

- `stockOnHand()`: `selling_value = round(quantity_on_hand * selling_price, 2)` по ред
  (магацин × артикл).
- `stockOnHandTotals()`: `total_selling_value = round(SUM(quantity_on_hand * selling_price), 2)`
  по артикл (преку сите магацини), паралелно со постоечкото `total_value`.

Ако `items.selling_price` е `NULL` (артикл без внесена продажна цена — реален
случај штом полето е ново), SQL множење со `NULL` дава `NULL`; мора експлицитно
да се третира со `COALESCE(items.selling_price, 0)` во `selectRaw` пресметките
(за `stockOnHandTotals`, каде се сумира преку SQL), односно `(float) ($row->selling_price ?? 0)`
во PHP-мапирањето (за `stockOnHand`, каде се пресметува во `map()`), така што
резултатот е секогаш `0`, никогаш `NULL`, а вкупниот збир никогаш не се "скршнува"
поради NULL-редови.

Продажната вредност е без ДДВ (иста конвенција како набавната вредност и како
самото поле `selling_price`).

## 2. Екран „Залиха" (`resources/views/livewire/inventory/stock-on-hand-report.blade.php`)

- Табелата за конкретен избран магацин добива нова колона **„Продажна вредност"**
  веднаш по постоечката, која се преименува во **„Набавна вредност"** (наместо
  сегашното „Вредност") за јасност штом стојат две вредносни колони една до
  друга. Colspan на празната состојба се менува од 5 на 6.
- Табелата „Вкупно за сите магацини" добива **„Вкупна продажна вредност"**, а
  постоечката „Вкупна вредност" се преименува во **„Вкупна набавна вредност"**.
  Colspan на празната состојба се менува од 4 на 5.
- Формат на прикажување: `\App\Support\Format::money($row['selling_value'], currency: '')`,
  иста конвенција како постоечката набавна вредност колона.
- На врвот на екранот (во истата картичка со филтерот за магацин, или веднаш до
  насловот) се додава линк **„Преземи PDF"**, стилски идентичен со партнерскиот
  (`partner-index.blade.php`: `text-brand hover:underline text-sm`), кој ја носи
  тековно избраната состојба (`warehouseId`, ако е избран) како query-параметар
  кон PDF рутата.

`StockOnHandReport::mount()`/`render()` не се менуваат структурно — само view-то
и `StockLevelQuery`.

## 3. PDF извоз

### Контролер

Нов `App\Http\Controllers\StockOnHandPdfController`, го следи истиот образец
како `PartnerListPdfController`:

```php
public function __invoke(Company $company, Request $request)
{
    Gate::authorize('view', $company);

    $warehouseId = $request->integer('warehouseId') ?: null;

    if ($warehouseId) {
        $rows = StockLevelQuery::stockOnHand($company, $warehouseId);
        $warehouseName = Warehouse::where('company_id', $company->id)->findOrFail($warehouseId)->name;
    } else {
        $rows = StockLevelQuery::stockOnHandTotals($company);
        $warehouseName = null;
    }

    $pdf = Pdf::loadView('pdf.stock-on-hand', compact('company', 'rows', 'warehouseName'));

    return $pdf->download('zaliha.pdf');
}
```

Еден blade view (`pdf.stock-on-hand`), со `@if($warehouseName)` гранење за
насловот и за колоната „Магацин" — истата структура како постоечкиот on-screen
`stock-on-hand-report.blade.php`, кој веќе гранее на истиот начин помеѓу режим
„конкретен магацин" и режим „вкупно".

Валидацијата дека `warehouseId` навистина припаѓа на таа компанија спречува
клиент да види туѓ магацин преку рачно менет query-параметар (истата тенант-
проверка конвенција веќе применета насекаде во проектот).

### View (`resources/views/pdf/stock-on-hand.blade.php`)

Целосно табелски distribution (`<table>`/`<td>`), **без `display:flex` или
`grid`** — dompdf 3.1.6 во оваа кодна база нема поддршка за нив (потврдено во
сп#3 „Sales Invoice PDF redesign" лекцијата). Визуелен стил идентичен со
`pdf/partner-list.blade.php` (брендиран акцент бар, наслов со име на фирма,
табела со `th`/`td` border-bottom).

Колони по ред: Шифра, Артикл, (Магацин — само во режим „сите магацини"),
Количина, Набавна вредност, Продажна вредност. Во режим „конкретен магацин"
насловот на PDF-от го содржи и името на магацинот.

## 4. Рута

Нова статична рута во постоечката `inventory.` рут-група
(`routes/web.php`, до `reports.stock-on-hand`):

```php
Route::get('/reports/stock-on-hand/pdf', [StockOnHandPdfController::class, '__invoke'])
    ->name('reports.stock-on-hand.pdf');
```

Статичен сегмент (`/pdf`), нема wildcard-судир — не бара специјално подредување
на рутите (за разлика од `partners/{partner}` случајот).

## 5. Тестирање

- **Unit** (`StockLevelQueryTest`): `selling_value`/`total_selling_value` се
  пресметуваат точно за нормален артикл со внесена продажна цена; се враќаат
  како `0` (не `null`) кога артиклот нема продажна цена; вкупниот збир во
  `stockOnHandTotals()` не се урива поради NULL-редови мешани со нормални.
- **Feature** (`StockOnHandReportTest`): новите колони („Набавна вредност",
  „Продажна вредност") се прикажуваат со точни износи, во двата режима
  (конкретен магацин / вкупно).
- **Feature** (нов `StockOnHandPdfTest`): авторизациски тестови (туѓа фирма →
  403, клиент/сметководител со пристап → 200); двата режими (конкретен магацин
  преку `?warehouseId=`, и вкупно без параметар); невалиден/туѓ `warehouseId` →
  404; **вистинска инспекција на PDF содржината** (текст-екстракција од
  генерираниот PDF, не само дека HTML/blade изгледа точно) за да се потврди
  дека и двете вредносни колони навистина се испечатени — продолжување на веќе
  воспоставената пракса во овој проект (сп#3 dompdf-flex инцидентот покажа дека
  HTML-string проверки не откриваат реални рендер-грешки во dompdf).

## Надвор од опфат (забележано, не сега)

- Вкупна вредност на цел магацин (сумирано преку сите артикли во тој магацин) —
  идна желба на корисникот, не е дел од овој сп#7.
- „Вреднување на залихи" (групирано резиме) не добива продажна вредност во овој
  сп#7.
