# Пуштање на субдомејните во продукција

Ова упатство е **еднократно**. Прво се прават четирите чекора подолу, точно по
овој редослед — DNS, Apache, сертификат и `.env` на серверот — и дури **потоа**
се спојува кодот во `main` и се пушта преку вообичаениот деплој (push → GitHub
Actions), како последен, петти чекор.

Зошто во овој редослед: новиот код за секое барање бара кое домејн име е
побарано и одлучува која апликација (Портал/Продажба/Финансии/Плата) да ја
прикаже; ако тоа име го нема во `.env` на серверот, кодот паѓа назад на
тестовски вредности (`portal.test` и слично) кои не постојат никаде во
продукција. Затоа: старите вредности во `.env` не пречат на стариот код (тој
воопшто не ги чита), но новиот код БЕЗ вистинските вредности во `.env`
значи дека ниту едно барање нема да се совпадне со ниту една рута — целиот
портал враќа грешка 404. Со тоа `.env` (чекор 4) мора да биде готов пред кодот
да се пушти (чекор 5), никогаш обратно.

Секој чекор кажува **на која машина се пушта**:

- **твојот компјутер** — во прелистувач, кај регистрарот каде е купен доменот
  `financebuddy.mk`, или кај GitHub за спојувањето на кодот;
- **серверот** — droplet-от, преку SSH сесија (`ssh root@46.101.177.209`).

⚠️ **Никогаш не мешај ги двете.** Ако си влезен со SSH на серверот, командите
за регистрарот не важат таму (и обратно). Пред да залепиш команда, погледни на
кој прозорец/таб си — на серверот терминалот обично покажува нешто како
`root@...:~#`.

Пред да почнеш, отвори SSH сесија кон серверот и остави ја отворена за чекори 2–4:

```
ssh root@46.101.177.209
```

---

## Чекор 1 — DNS записи

**Машина: твојот компјутер, во прелистувач кај регистрарот.**

Влези во контролната табла на регистрарот кај кого е купен `financebuddy.mk` и
додади три нови `A` записи. Ако веќе постои запис за `portal`, копирај му ги
поставките и само промени го името:

| Тип | Име (host) | Вредност (points to) |
|---|---|---|
| A | `prodazba` | `46.101.177.209` |
| A | `finansii` | `46.101.177.209` |
| A | `plata` | `46.101.177.209` |

**Како да провериш дека успеало:** Ова не се гледа веднаш — DNS записите
треба време да се рашират (обично неколку минути, некогаш и подолго). На твојот
компјутер, отвори нов терминал (не SSH сесијата кон серверот!) и провери:

```
ping prodazba.financebuddy.mk
```

Успеало кога во одговорот пишува истата адреса `46.101.177.209` (самиот ping
не мора да добие одговор од серверот — важно е адресата да е точна). Повтори
за `finansii.financebuddy.mk` и `plata.financebuddy.mk`. Ако пишува "could not
find host" или слично, почекај уште малку и пробај пак пред да продолжиш на
чекор 2.

## Чекор 2 — Apache: додај ги новите имиња на постојниот сајт

**Машина: серверот (SSH сесијата).**

Прво пронајди го фајлот со поставките (vhost) што веќе го опслужува
`portal.financebuddy.mk`:

```
grep -l "portal.financebuddy.mk" /etc/apache2/sites-enabled/*
```

**Што треба да видиш:** една патека, на пример
`/etc/apache2/sites-enabled/portal.financebuddy.mk-le-ssl.conf`. Запамети ја —
таа ти треба во следниот потчекор. Ако излезат две патеки (обично има и една
без TLS/443), отвори ги двете исто.

Отвори го фајлот за уредување (замени `<ПАТЕКА>` со патеката од горе):

```
nano <ПАТЕКА>
```

Во фајлот, пронајди ја линијата што почнува со `ServerName
portal.financebuddy.mk`. Веднаш под неа додади нова линија (или, ако веќе
постои линија `ServerAlias`, дополни ја со трите имиња):

```
    ServerAlias prodazba.financebuddy.mk finansii.financebuddy.mk plata.financebuddy.mk
```

Зачувај и излези: `Ctrl+O`, потоа `Enter` (зачувај), потоа `Ctrl+X` (излез).
Ако имаше и втор фајл (без `-le-ssl`), повтори истата измена и во него.

Провери дали поставките се исправни:

```
apachectl configtest
```

**Што треба да видиш:** `Syntax OK`. Ако пишува било што друго (грешка со
линија и број), не продолжувај — врати се во `nano` и провери ја линијата што
ја додаде.

Дури откако ќе видиш `Syntax OK`, вчитај ги новите поставки:

```
systemctl reload apache2
```

**Што треба да видиш:** командата завршува без порака и без грешка (се враќаш
директно на `root@...:~#`). Тоа значи успех — `reload` не пишува ништо кога е
се во ред.

## Чекор 3 — Сертификат (HTTPS) за новите имиња

**Машина: серверот (SSH сесијата).**

Ова мора да чека DNS-от од чекор 1 веќе да се раширил (провери пак со `ping`
ако помина малку време од чекор 1), инаку certbot нема да може да ги потврди
новите имиња.

```
certbot --apache -d portal.financebuddy.mk -d prodazba.financebuddy.mk -d finansii.financebuddy.mk -d plata.financebuddy.mk
```

Certbot може да праша нешто во тек на процесот (на пример, дали да продолжи
со проширување на постојниот сертификат) — избери го понудениот стандарден
одговор со `Enter`.

**Што треба да видиш:** порака што почнува со нешто како
`Successfully received certificate` и на крај листа на четирите домени со
патеки до сертификатот (`/etc/letsencrypt/live/portal.financebuddy.mk/...`).
Ако пишува грешка со зборот `Challenge failed` за некое од новите имиња,
DNS-от сѐ уште не стигнал секаде — почекај и пробај ја истата команда повторно.

Брза проверка на секоја од трите нови адреси во прелистувач на твојот
компјутер (`https://prodazba.financebuddy.mk` и сл.) — успеало кога
прелистувачот не пишува предупредување за несигурна врска. Екранот што ќе се
отвори сè уште нема да работи целосно (тоа доаѓа дури по чекор 4, а старото
мени на порталот сè уште ќе се гледа сè до чекор 5) — тоа е нормално на ова
место во упатството.

## Чекор 4 — `.env` на серверот и чистење кеш

**Машина: серверот (SSH сесијата).**

Најди ја папката на апликацијата (истата од која работи порталот денес):

```
find / -maxdepth 4 -name artisan -type f 2>/dev/null
```

**Што треба да видиш:** една патека што завршува на `/artisan`, на пример
`/var/www/tami-web-app/artisan`. Папката (без `/artisan` на крајот) е местото
каде што работиш понатаму.

Оди во таа папка (замени ја патеката со твојата):

```
cd /var/www/tami-web-app
nano .env
```

Во `.env`, пронајди ги следниве четири линии и внеси ги вистинските имиња
(веројатно веќе постои линија за `APP_DOMAIN_PORTAL` со `portal.financebuddy.mk`
— само провери ја; додади ги другите три ако ги нема):

```
APP_DOMAIN_PORTAL=portal.financebuddy.mk
APP_DOMAIN_PRODAZBA=prodazba.financebuddy.mk
APP_DOMAIN_FINANSII=finansii.financebuddy.mk
APP_DOMAIN_PLATA=plata.financebuddy.mk
```

Потоа пронајди ја линијата `SESSION_DOMAIN=` и промени ја вредноста да биде
точно (со точката на почетокот — таа е она што прави едно најавување да важи
на сите четири адреси):

```
SESSION_DOMAIN=.financebuddy.mk
```

Зачувај и излези: `Ctrl+O`, `Enter`, `Ctrl+X`.

Исчисти го стариот кеш и направи нов (со стари вредности сеуште кеширани,
апликацијата ќе продолжи да го игнорира она што штотуку го запиша во `.env`):

```
php artisan config:clear && php artisan config:cache
```

**Што треба да видиш:** две пораки по ред —
`INFO  Configuration cache cleared successfully.` (од `config:clear`) и
`INFO  Configuration cached successfully.` (од `config:cache`). Ако видиш
црвена порака со `ERROR`, не продолжувај — провери дали `.env` е зачуван
правилно (чекор погоре) пред да пробаш пак.

Секој деплој (чекор 5) исто така прави `php artisan route:cache`, кое ги
"пече" домејните во кеш на рутите, одделно од кешот на поставките што штотуку
го обнови. Затоа обнови го и него овде, инаку кешираните рути сè уште ги носат
старите (тестовски) домејни дури и откако `.env` е точен:

```
php artisan route:clear && php artisan route:cache
```

**Што треба да видиш:** две пораки по ред —
`INFO  Route cache cleared successfully.` (од `route:clear`) и
`INFO  Routes cached successfully.` (од `route:cache`). Иста постапка како
погоре ако видиш `ERROR`.

⚠️ **Секој ќе биде одјавен еднаш.** Со промената на `SESSION_DOMAIN`, старото
колаче за сесија (врзано за еден хост) повеќе не важи — секој веќе најавен
човек (тебе вклучен) ќе мора да се најави пак по овој чекор. Тоа е нормално и
очекувано, не е дефект.

Во овој момент сајтот сè уште работи со стариот код (тоа е нормално и очекувано)
— новите домејни само добија точни вредности во `.env`, подготвени за кога ќе
се пушти новиот код во чекор 5.

## Чекор 5 — Пуштање на кодот

**Машина: твојот компјутер (или GitHub во прелистувач).**

Дури сега, откако чекори 1–4 се завршени, се спојува кодот за субдомејните во
`main` и се пушта (push). Тоа автоматски поведува GitHub Actions да го распостави
на серверот, исто како секој друг деплој досега.

**Што треба да видиш:** во GitHub Actions, зелена ознака за завршениот workflow
("деплој успешен"/зелена кукичка), без црвена грешка.

## Проверка по сите пет чекора

**Машина: твојот компјутер, во прелистувач.**

Отвори ги трите нови адреси една по една:
`https://prodazba.financebuddy.mk`, `https://finansii.financebuddy.mk`,
`https://plata.financebuddy.mk`.

Успеало кога на секоја: страницата се отвора без предупредување за
сигурност, те бара најава (или те пушта директно ако веќе си најавен), а
сајдбарот покажува мени соодветно на таа апликација (Продажба / Финансии /
Плата), не целото старо мени од порталот.

Ако при првата најава по деплојот прелистувачот покаже „419 Page Expired“,
тоа не е расипан деплој — тоа е старото колаче за сесија што сè уште стои од
пред промената на `SESSION_DOMAIN`. Избриши ги колачињата за
`financebuddy.mk` (или отвори приватен прозорец) и најави се пак.

## Ако нешто тргне наопаку

Ако по невнимание кодот се пушти (чекор 5) пред `.env` на серверот да е
подготвен (чекор 4), порталот ќе почне да враќа грешка 404 на сите адреси —
и `portal.financebuddy.mk`, и трите нови. Тоа изгледа страшно, но не е —
никакви податоци не се губат, само рутите привремено не се совпаѓаат.

Поправката бара две чистења кеш, не само едно: рутите се кешираат одделно од
поставките, па само `config:cache` не е доволно — старите (тестовски) домејни
остануваат кеширани во рутите и сите адреси продолжуваат да враќаат 404.
Врати се на чекор 4 и направи го целосно (внеси ги четирите `APP_DOMAIN_*`
вредности и `SESSION_DOMAIN=.financebuddy.mk` во `.env`, потоа):

```
php artisan config:clear && php artisan config:cache
php artisan route:clear && php artisan route:cache
```

Штом двата кеша се обноват, сајтот веднаш се враќа во нормала — нема потреба
од ништо друго.
